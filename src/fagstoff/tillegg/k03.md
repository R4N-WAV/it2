## Læringsmål

Etter dette kapittelet skal du kunne:

- forklare **input – processing – output** og bruke det til å beskrive et hvilket som helst lite program,
- forklare hva en **algoritme** er og skrive en enkel algoritme i **pseudokode** og Python,
- forklare **variabel**, **datatype**, **betingelse**, **løkke**, **funksjon**, **parameter** og **returverdi** med egne ord og eksempler,
- **spore** (trace) et lite program: skrive ned verdiene til variablene linje for linje,
- bryte ned en oppgave i trinn og finne **grenseverdier** og **spesialtilfeller**,
- forklare forskjellen på `print` og `return`, og på `=` og `==`.

> TIPS: Du trenger ikke å kunne skrive store programmer uten hjelp. Men du må kunne **lese** kode høyt, forklare hva den gjør, og gjøre små endringer. Øv på å spore kode med penn og papir.

## Flere eksempler

### Eksempel 1 (enkelt): Spore et program

```python
sum = 0
for tall in [3, 5, 2]:
    sum = sum + tall
print(sum)
```

| Steg | `tall` | `sum` etter linjen |
|---|---:|---:|
| start | – | 0 |
| 1. runde | 3 | 3 |
| 2. runde | 5 | 8 |
| 3. runde | 2 | 10 |

Utskrift: `10`. Å lage slik en tabell er den beste måten å forstå (og forklare) en løkke på.

### Eksempel 2 (middels): Liste eller ordbok?

Du skal lagre antall elever per klasse og slå opp «hvor mange går i 2STA?».

```python
# Liste: må lete gjennom alt
klasser = [["2STA", 28], ["2STB", 26]]
for navn, antall in klasser:
    if navn == "2STA":
        print(antall)

# Ordbok: direkte oppslag med nøkkel
klasser = {"2STA": 28, "2STB": 26}
print(klasser["2STA"])
```

Ordboken passer bedre fordi vi slår opp via en meningsfull **nøkkel**. Listen passer når rekkefølgen er viktig, for eksempel temperaturer per time.

### Eksempel 3 (sammensatt): Finn alle over en grense og returner dem

```python
def over_grense(verdier, grense):
    resultat = []
    for v in verdier:
        if v > grense:
            resultat.append(v)
    return resultat

print(over_grense([4, 12, 9, 15], 10))   # [12, 15]
```

Her samles fire byggeklosser: **parameter** (`grense`), **løkke**, **betingelse** og **returverdi**. Fordi grensen er en parameter, kan samme funksjon brukes for 10, 100 eller 0 – det er begynnelsen på gjenbrukbar kode (kapittel 8).

## Gjennomarbeidet eksempel

**Oppgave:** Lag en funksjon som returnerer **gjennomsnittet** av en liste, og som håndterer tom liste.

1. *Én setning:* Funksjonen tar en liste med tall og returnerer gjennomsnittet.
2. *Input:* liste med tall. *Output:* et tall, eller `None` hvis listen er tom.
3. *Regler:* gjennomsnitt = sum / antall. *Spesialtilfelle:* tom liste gir deling på null.
4. *Pseudokode:*

```text
FUNKSJON gjennomsnitt(liste)
    HVIS liste er tom
        RETURNER ingen_verdi
    total = 0
    FOR hvert tall i liste
        total = total + tall
    RETURNER total / antall elementer i liste
```

5. *Python:*

```python
def gjennomsnitt(liste):
    if len(liste) == 0:
        return None
    total = 0
    for tall in liste:
        total += tall
    return total / len(liste)
```

6. *Test:* `[2, 4, 6]` → 4.0 (normal), `[5]` → 5.0 (ett element), `[]` → `None` (spesialtilfelle), `[-2, 2]` → 0.0 (negative tall).

7. *Begrunnelse:* Jeg sjekker tom liste **først**, fordi resten av koden ellers krasjer med `ZeroDivisionError`. Et alternativ er å bruke `sum(liste)`, som er kortere; den manuelle løkka viser bare tydeligere hva som skjer.

## Sensoroppfølging

1. «Hvorfor må `poeng >= 80` stå før `poeng >= 60`?» – `elif` velger første sanne gren; 85 ville ellers fått B.
2. «Hva er forskjellen på `print` og `return`?» – `print` viser på skjermen, `return` gir verdien tilbake så den kan brukes videre og testes.
3. «Når bruker du `while` i stedet for `for`?» – Når antall gjentakelser ikke er kjent på forhånd (f.eks. til brukeren skriver riktig passord).
4. «Hvordan vet du at løkka stopper?» – Noe i løkka må endre betingelsen (teller økes).
5. «Hva er O(n)?» – Tidsbruken vokser omtrent proporsjonalt med antall elementer.

## Oppgaver og løsningsforslag

:::oppgave Grunnleggende
1. Forklar forskjellen mellom en variabel, en funksjon og en løkke.
:::losning
Variabel: et navn som holder en verdi (`pris = 100`). Løkke: gjentar en kodeblokk (`for vare in handlekurv:`). Funksjon: navngitt, gjenbrukbar kodeblokk med parametere og returverdi (`def totalpris(handlekurv): …`). De brukes sammen: en funksjon bruker ofte en løkke og variabler internt.
:::

:::oppgave Grunnleggende
2. Hva blir resultatet av `x = 4; x = x + 3; print(x)`? Forklar trinnene.
:::losning
`7`. Først får `x` verdien 4. Så regnes høyresiden `x + 3` ut med den gamle verdien (4 + 3 = 7), og resultatet lagres i `x`. Til slutt skrives 7 ut. Merk at `=` betyr *tilordning*, ikke matematisk likhet.
:::

:::oppgave Grunnleggende
3. Skriv pseudokode som sjekker om et tall er positivt, negativt eller null.
:::losning
```text
LES tall
HVIS tall > 0
    VIS "positivt"
ELLERS HVIS tall < 0
    VIS "negativt"
ELLERS
    VIS "null"
```
Test med 5, -3 og 0 (grenseverdien).
:::

:::oppgave Middels
4. Lag en funksjon som tar imot en liste med tall og returnerer summen.
:::losning
```python
def summer(talliste):
    total = 0
    for tall in talliste:
        total += tall
    return total
```
`summer([1, 2, 3])` gir 6, `summer([])` gir 0 (som er riktig for en tom sum). Alternativ: `return sum(talliste)`.
:::

:::oppgave Middels
5. Lag en algoritme som teller hvor mange tall i en liste som er større enn 10.
:::losning
```python
def tell_over_ti(talliste):
    antall = 0
    for tall in talliste:
        if tall > 10:
            antall += 1
    return antall
```
Test: `[]` → 0, `[10]` → 0 (grenseverdi: 10 er *ikke* større enn 10), `[11, 3, 20]` → 2.
:::

:::oppgave Middels
6. Tegn eller beskriv et flytskjema som beregner rabatt: 10 % hvis kjøpet er over 500 kr, ellers ingen rabatt.
:::losning
START → (parallellogram) LES beløp → (rombe) beløp > 500? → **ja:** (rektangel) pris = beløp × 0,9 → **nei:** (rektangel) pris = beløp → begge piler til (parallellogram) VIS pris → (oval) SLUTT. Test grensen: 500 gir ingen rabatt, 501 gir rabatt. Spør også oppdragsgiver om «over 500» egentlig betyr «fra og med 500» – det er en kravavklaring.
:::

:::oppgave Utfordrende
7. Lag en funksjon som finner gjennomsnittet i en liste, men som håndterer tom liste.
:::losning
Se det gjennomarbeidede eksempelet. Kjernen: sjekk `len(liste) == 0` først og returner `None` (eller kast en feil hvis tom liste ikke skal være lov), ellers `sum(liste) / len(liste)`. Begrunn valget: `None` gjør at kallende kode må håndtere tilfellet eksplisitt.
:::

:::oppgave Utfordrende
8. Forklar hvorfor en lineær søkealgoritme kan være enklere enn binærsøk, selv om binærsøk ofte er raskere.
:::losning
Lineært søk sjekker elementene ett for ett. Det er lett å skrive og forstå, og virker på **usorterte** data. Binærsøk halverer søkeområdet hvert steg (O(log n)) og er mye raskere på store mengder, men krever at dataene er **sortert** og er vanskeligere å implementere riktig (grenser og midtpunkt). For en liste med 20 elementer er forskjellen ubetydelig, og hvis dataene må sorteres først, kan sorteringen koste mer enn søket sparer. Valget avhenger av datamengde, hvor ofte man søker og om dataene allerede er sortert.
:::

## Vanlige feil

- `=` (tilordning) brukt der man mener `==` (sammenligning).
- Feil rekkefølge på `if/elif`, så en bred test «stjeler» tilfellene.
- Glemmer å oppdatere telleren i en `while`-løkke → uendelig løkke.
- `print` i stedet for `return`, så funksjonen returnerer `None`.
- Blander tekst og tall: `"19" + "1"` blir `"191"`.
- Starter `storst = 0` i stedet for `liste[0]` – feil når alle tallene er negative.
- Indeks utenfor listen: en liste med 3 elementer har indeks 0, 1, 2.

## Huskeliste

- Input → processing → output.
- Algoritme: endelig, entydig, har stopp og resultat.
- Datatyper: int, float, str, bool, liste, dict.
- `if/elif/else` velger første sanne gren – rekkefølgen betyr noe.
- `for` = kjent samling, `while` = så lenge betingelse er sann.
- Funksjon: parametere inn, `return` ut.
- Spor koden med verditabell. Test normal, grense og ugyldig.
