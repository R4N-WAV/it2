## Læringsmål

Etter dette kapittelet skal du kunne:

- forklare **klasse** og **objekt** (mal og instans) med eget eksempel,
- forklare **attributt**, **metode**, **konstruktør** (`__init__`) og `self`, og peke på dem i kode,
- skrive en enkel klasse med validering i metodene (**innkapsling**: objektet skal aldri havne i ugyldig tilstand),
- bruke **arv** med `super().__init__` og **overstyre** en metode,
- forklare **polymorfisme** med et eksempel der en løkke behandler ulike objekter likt,
- velge mellom **arv** («er-en») og **komposisjon** («har-en») og begrunne valget,
- vurdere når OOP **ikke** er nødvendig.

> EKSAMEN: OOP er et kritisk område. Du må kunne forklare begrepene *og* vise dem i kode. Øv særlig på å si: «Her er klassen, her lager jeg to objekter, her er attributtene, her er en metode som endrer tilstanden, og her hindrer jeg ugyldig tilstand.»

## Flere eksempler

### Eksempel 1 (enkelt): Klassen `Elev`

```python
class Elev:
    def __init__(self, navn, klasse):
        self.navn = navn            # attributt
        self.klasse = klasse        # attributt
        self.fravaer = 0            # attributt med startverdi

    def registrer_fravaer(self, timer):   # metode
        if timer > 0:
            self.fravaer += timer

a = Elev("Sara", "2STA")     # objekt 1
b = Elev("Ali", "2STB")      # objekt 2
a.registrer_fravaer(2)
print(a.fravaer, b.fravaer)  # 2 0
```

`a` og `b` er laget fra samme klasse, men har **egen tilstand**. `self` i metoden er det objektet metoden kalles på – her `a`.

### Eksempel 2 (middels): Arv med `super()`

```python
class Person:
    def __init__(self, navn):
        self.navn = navn

    def presenter(self):
        return f"Jeg heter {self.navn}"

class Student(Person):
    def __init__(self, navn, studiested):
        super().__init__(navn)          # gjenbruker konstruktøren i Person
        self.studiested = studiested

    def presenter(self):                # overstyring
        return super().presenter() + f" og studerer ved {self.studiested}"

print(Student("Mina", "OsloMet").presenter())
```

`Student` **er en** `Person`, så arv passer. `super().__init__(navn)` gjør at vi ikke kopierer koden som setter navn (DRY). Uten den linjen ville `self.navn` aldri blitt satt, og `presenter()` ville krasjet med `AttributeError`.

### Eksempel 3 (sammensatt): Polymorfisme med betalingsmetoder

```python
class Betaling:
    def betal(self, belop):
        raise NotImplementedError

class Kort(Betaling):
    def betal(self, belop):
        return f"Trekker {belop} kr fra kort"

class Vipps(Betaling):
    def betal(self, belop):
        return f"Sender Vipps-forespørsel på {belop} kr"

class Gavekort(Betaling):
    def __init__(self, saldo):
        self.saldo = saldo
    def betal(self, belop):
        if belop > self.saldo:
            return "For lite på gavekortet"
        self.saldo -= belop
        return f"Gavekort: {belop} kr trukket, {self.saldo} igjen"

for metode in [Kort(), Vipps(), Gavekort(100)]:
    print(metode.betal(80))
```

Kassen trenger ikke `if type == ...`. Den kaller `betal` og hvert objekt gjør sin versjon. Ny betalingsmetode = ny klasse, ingen endring i kassen. Det er **polymorfisme** og gjør koden lett å **utvide**.

### Komposisjon: bil og motor


`Bil` **har en** `Motor` (komposisjon). `Elbil` **er en** `Bil` (arv).

## Gjennomarbeidet eksempel

**Oppgave:** Lag `Sparekonto` med saldo, innskudd og uttak. Hindre negativt uttak og uttak over saldo.

1. *Data (attributter):* eier, saldo. Saldo skal ikke kunne bli negativ → markeres intern med `_saldo`.
2. *Oppførsel (metoder):* `sett_inn(belop)`, `ta_ut(belop)`, `hent_saldo()`.
3. *Regler:* beløp må være > 0; uttak ≤ saldo; startsaldo ≥ 0.

```python
class Sparekonto:
    def __init__(self, eier, startbelop=0):
        if startbelop < 0:
            raise ValueError("Startbeløp kan ikke være negativt")
        self.eier = eier
        self._saldo = startbelop

    def hent_saldo(self):
        return self._saldo

    def sett_inn(self, belop):
        if belop <= 0:
            return False
        self._saldo += belop
        return True

    def ta_ut(self, belop):
        if belop <= 0 or belop > self._saldo:
            return False
        self._saldo -= belop
        return True
```

4. *Test:*

| Test | Handling | Forventet |
|---|---|---|
| T1 | `Sparekonto("Mina", 500)` | saldo 500 |
| T2 | `ta_ut(500)` | `True`, saldo 0 (grense) |
| T3 | `ta_ut(1)` på saldo 0 | `False`, saldo 0 |
| T4 | `sett_inn(-50)` | `False` |
| T5 | `Sparekonto("X", -1)` | `ValueError` |

5. *Begrunnelse:* Reglene ligger **i klassen**, så ingen annen del av programmet kan glemme dem. Metodene returnerer `True/False` slik at brukergrensesnittet kan gi en forståelig beskjed. Alternativ: kaste unntak ved ugyldig uttak – tydeligere for utviklere, men krever `try/except` der metoden brukes.

## Sensoroppfølging

1. «Hva er forskjellen på en klasse og et objekt?» – Mal vs. konkret instans med egne verdier.
2. «Hva gjør `self`?» – Peker på objektet metoden kalles på, så metoden endrer riktig objekts tilstand.
3. «Hvorfor lager du ikke bare attributtet offentlig og endrer det direkte?» – Da kan man omgå valideringen (innkapsling).
4. «Hva skjer hvis du glemmer `super().__init__`?» – Superklassens attributter settes ikke → `AttributeError`.
5. «Hvordan ville du lagt til en ny type uten å endre eksisterende kode?» – Ny subklasse som overstyrer metoden (polymorfisme).

## Oppgaver og løsningsforslag

:::oppgave Grunnleggende
1. Forklar forskjellen mellom en klasse og et objekt.
:::losning
En klasse er en mal som beskriver hvilke attributter og metoder objektene skal ha (`class Hund`). Et objekt er en konkret instans laget fra klassen (`luna = Hund("Luna", 4)`), med egne verdier. Mange objekter kan lages fra samme klasse.
:::

:::oppgave Grunnleggende
2. Hva er et attributt, en metode og en konstruktør?
:::losning
Attributt: data som hører til objektet (`self.saldo`). Metode: funksjon definert i klassen som bruker/endrer objektets data (`def ta_ut(self, belop)`). Konstruktør: spesialmetoden (`__init__` i Python) som kjøres når objektet lages og setter gyldige startverdier.
:::

:::oppgave Grunnleggende
3. Hva gjør `self` i Python?
:::losning
`self` er en referanse til det objektet metoden kalles på. Når vi skriver `konto1.sett_inn(100)`, er `self` lik `konto1` inne i metoden, så `self.saldo += 100` endrer bare den kontoen. `self` må stå som første parameter i metodene.
:::

:::oppgave Middels
4. Lag klassene `Person` og `Student`, der `Student` arver fra `Person`. Forklar hvorfor arv passer.
:::losning
Se eksempel 2 over. Arv passer fordi en student **er en** person: alt en person har (navn) har også en student, og studenten legger til egne attributter (studiested). Vi gjenbruker konstruktøren med `super().__init__` og kan overstyre `presenter()`.
:::

:::oppgave Middels
5. Lag en klasse `Sparekonto` med saldo, innskudd og uttak. Hindre negativt uttak og uttak over saldo.
:::losning
Se det gjennomarbeidede eksempelet over, inkludert testtabell. Kjernen er at `ta_ut` sjekker `belop <= 0 or belop > self._saldo` før saldoen endres.
:::

:::oppgave Middels
6. Forklar hvorfor `Bil` og `Motor` ofte bør forbindes med komposisjon i stedet for arv.
:::losning
Fordi forholdet er «har-en», ikke «er-en»: en bil har en motor, men en motor er ikke en bil. Med arv ville `Motor` fått bilens attributter (merke, antall seter), som er meningsløst. Med komposisjon kan bilen bytte motor (bensin, elektrisk) og motoren kan testes separat.
:::

:::oppgave Utfordrende
8. Et program har én superklasse med 15 underklasser. Vurder når arvtreet kan være for komplisert og foreslå alternativ struktur.
:::losning
Det er for komplisert hvis underklassene bare skiller seg på data (f.eks. pris eller farge) og ikke på oppførsel – da holder det med ett attributt. Alternativer: komposisjon (et objekt *har* en motor-type og en strategi for beregning), færre klasser med attributter, eller grensesnitt der bare oppførselen som faktisk varierer, er egne klasser.
:::

## Vanlige feil

- Glemmer `self` som første parameter → `TypeError: takes 1 positional argument but 2 were given`.
- Glemmer `super().__init__(...)` i subklassen.
- Bruker arv for «har-en»-forhold (Bil arver Motor).
- Lager klasser som bare er databokser uten metoder, mens all logikk ligger utenfor.
- Endrer attributter direkte utenfra og omgår valideringen.
- Forveksler klassen med objektet: `Konto.saldo` i stedet for `min_konto.saldo`.

## Huskeliste

- Klasse = mal. Objekt = instans med egen tilstand.
- Attributt = data. Metode = oppførsel. Konstruktør = `__init__` setter gyldig start.
- `self` = objektet metoden kalles på.
- Innkapsling: reglene ligger i metodene; `_navn` = internt.
- Arv: er-en, `class B(A)`, `super().__init__()`, overstyring.
- Polymorfisme: samme metodenavn, ulik oppførsel.
- Komposisjon: har-en, ofte mer fleksibelt.
